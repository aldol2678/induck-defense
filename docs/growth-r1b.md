- 50 ms 고정 tick, 맵 JSON(SHA-256 `7e79062e…a99b`), 기존 replay 포맷(`induck-replay/1`)은 그대로입니다. 성장 replay에는 선택 필드 `growth: { blueprints }`만 추가됩니다.

## 1. 장비: 설계도 확인 → 판 내 제작 → 유닛당 1슬롯
| 명령 | 조건 | 거부 사유 |
|---|---|---|
| `CRAFT_EQUIPMENT { blueprintId }` | 런 스냅샷에 있는 설계도 + 실제 전투에 구현된 옵션 + 전투 코인 | `NOT_OWNED`, `UNSUPPORTED_OPTION`, `NO_FUNDS`, `PHASE_BLOCKED` |
| `EQUIP { unitId, itemId }` | 보관함에 있는 아이템, 전공 일치(공용은 전부) | `NO_UNIT`, `NO_ITEM`, `MAJOR_MISMATCH` |
| `UNEQUIP { unitId }` | 장착 중일 때 | `NOT_EQUIPPED` |

- 제작 비용(전투 코인, 시험값): 일반 30 · 희귀 45 · 영웅 60 · 전설 80. 영웅·전설 장비는 지금 모두 미구현 옵션이라 실제로 제작할 수는 없습니다.
- 이미 장착한 유닛에 다른 아이템을 장착하면 기존 아이템은 보관함으로 돌아갑니다. 슬롯은 항상 1칸입니다.
- 아이템 id는 `g1, g2…`로 별도 카운터를 씁니다. 유닛·적 id(`nextEntityId`)와 게임 RNG는 건드리지 않습니다.
- UI: 🔬 연구 화면(웨이브 사이) → 🧰 장비 공방. 보드에서 유닛을 탭해 선택한 뒤 열면 장착·해제할 수 있습니다.

## 2. 고유 특성·합성 계승
- 소환할 때 게임 RNG는 R0와 똑같이 1) 전공 2) 칸 순서로 씁니다. 특성은 **별도 스트림**(`traitStreamSeed(seed)`)에서 매번 2회 뽑습니다(등급 → 등급 안의 특성). 그래서 같은 시드면 전공·칸 시퀀스가 R0와 같습니다(테스트로 확인).
- 등급 확률 70/22/7/1(일반/희귀/영웅/전설, 시험값). 특성 목록은 `src/core/growth.ts` `TRAITS`에 있고, 목록 순서도 replay 계약에 포함됩니다.
- 같은 전공·같은 ★ 합성에서 두 특성이 다르면 `DROP_UNIT`에 `inherit: 'target' | 'source'`가 있어야 합니다. 없으면 `CHOICE_REQUIRED`로 거부되고 **아무것도 바뀌지 않습니다**(유닛·장비·코인·두 RNG 모두). UI는 이때 일시정지하고 선택 창을 띄웁니다. 취소하면 명령을 보내지 않고 재개합니다.
- 합성 결과(자리 유닛)는 자기 장비를 유지하고, 재료 유닛의 장비는 보관함으로 돌아갑니다(`EQUIPMENT_RETURNED`). 특성이 같으면 선택 없이 합성되고, ★4끼리는 기존처럼 `MAX_STAR`가 먼저 적용됩니다.

## 3. 실제 전투 옵션과 반올림 손실 해소
- 구현된 옵션: **피해 %, 공격속도 %, 사거리(1/100칸)**. 특성과 장비 효과를 더해서 적용합니다.
- 미구현 옵션은 🧰 화면에 "사용불가 · 미구현(스킬형/상태이상/조건부/경제/지원·오라 효과)"로 표시하고 제작할 수 없습니다. 예: 병렬 연산 칩, 둔화 장갑, 형광펜, 논리 분석 노트, 학생증 목걸이 등.
- 피해는 1/100 단위 고정소수점으로 계산하고 남은 몫을 유닛별로 이월합니다(`damageWithCarry`). 예: 3 피해에 +8%면 R0식 반올림으로는 100타에 300이지만, 이 방식으로는 정확히 324입니다. 보너스 0%면 R0와 값이 같습니다.
- 공격 주기도 1/100 tick 단위로 이월합니다(`cooldownWithCarry`). R0의 700/900/1000 ms는 보너스 0%일 때 기존 tick 수와 같습니다.
- 문과대 약점(×1.25)은 R0 규칙 그대로 정수 피해에 반올림해서 적용합니다(시험값 미결이라 바꾸지 않았습니다).
